# Evidence contract — Phase 3A

Interpretation can be probabilistic. Money cannot.

`EvidenceCandidate` is an untrusted typed extraction, not financial authorization. A future extractor targets the JSON format produced by `to_json`; decimal fields are strings and dates have distinct ISO meanings. `from_json` validates transport shape without treating a successful parse as accepted cash. Negative/zero/nonfinite values can reach semantic validation and cannot bypass it by parsing successfully.

`EvidenceSource` carries MESSAGE/IMAGE identity, user/request/event associations, observed timestamp and an optional trusted publisher identity. Message source categories such as bank/employer are not unique publisher identifiers. Unknown image timing/currency stays unknown. Candidate `original_label` preserves the extracted semantic label; it is never interpreted as an instruction.

Fact types distinguish salary, expense/rent, receipt, refund/reimbursement, approved invoice, pending payout, investment value/sale, cancellation, reschedule, employment ended and final payroll. Salary amount versus ongoing change uses scope plus explicit-amendment metadata, not separate enums for every wording. Amount meaning distinguishes net/gross pay, invoice total/balance/paid, tax, subtotal, late fee, valuation, sale proceeds and account balance. Scope distinguishes one event/next occurrence from ongoing/from/until/one-off applicability. Effective, payment, due and period dates are separate; date-dependent bill tiers can be represented as scoped candidates and may remain unresolved if the applicable tier is unknown.

`EvidenceDecision` is ACCEPTED, REJECTED or UNRESOLVED with a machine-readable reason. Only validation can wrap a candidate in `ValidatedEvidenceFact`; later reconciliation can still find conflicts. Confidence is diagnostic and never authorizes cash. `EvidenceBatch.exhaustive` tracks whether a source has been fully accounted for; one accepted number does not establish that a cropped image has been resolved.

Checkpoint A provides only schema/transport/tests. Checkpoint B must implement validation and deterministic normalized amendments, and Checkpoint C connects those amendments through a typed forecast interface. No external extractor, prompt, credential, API or model usage is part of Phase 3A. No sample label belongs in production.

## Deterministic validation and reconciliation (Checkpoint B)

Canonical source records come from trusted request context, not the candidate. User/request/event associations and source timestamps must match. Missing currency/date/amount, nonpositive monetary amounts, unsupported scope, and contradictions stay UNRESOLVED. Clearly hypothetical/conditional income, valuation and contextual gross/subtotal/tax/account-balance figures are REJECTED as non-cash. Confidence has no acceptance threshold. Confirming a pending credit is not settlement; no cash is authorized without the appropriate state.

Reconciliation validates candidates itself and groups by exact linked event or explicit external obligation key. Compatible facts coalesce. Explicit event cancellation takes priority over schedules; a later explicit amendment can supersede older evidence only with the same known publisher identity. Unknown/different publishers and ties remain unresolved. No LLM chooses conflicts. A differing CSV amount requires an explicit amendment; missing outstanding amount requires balance_due semantics. Total is not assumed to equal remaining liability. A fully settled linked bill becomes historical snapshot evidence, not another expense; partial-paid arithmetic remains unresolved without explicit remaining balance.

NormalizedEvidenceState contains immutable event copies, accepted amendment provenance, confirmed future credit identities, and scoped SeriesAmendment directives. It contains no balance or affordability calculation. Next-pay amounts change one event; ongoing amounts explicitly direct later matched projections. Reschedules retain the same event ID; cancelled/paid occurrences get a suppression directive so history cannot re-create them. Final payroll and employment-ended facts stop matched inferred continuation, not unrelated income. New refund/reimbursement/sale/invoice cash is one-off, requires explicit currency/date/category/reference and cannot overwrite a generic matching CSV event. Original linked_event_id values remain lifecycle relationships.

Uncertain document tiers, partial payments, cross-currency amendments, ambiguous source identity and missing observation dates deliberately remain unresolved. Image metadata has no timestamp: the later evidence layer must establish observation context rather than silently assume it. No image values from real samples are fixtures in production.
